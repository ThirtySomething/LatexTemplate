\section{Tables}

Font sizes play a role in the use of tables when it comes to distributing
the content appropriately among the columns. Here is a sample code how to
make a table.

\begin{figure}[H]
    \small
    \centering
    \begin{BVerbatim}
\begin{small}
    \renewcommand*{\arraystretch}{3}
    \begin{longtable}{ | p{0.43\linewidth} | p{0.5\linewidth} | }
        \hline
        \tsTextBold{Command}       & \tsTextBold{Sample} \\
        \hline
        \endhead
        \{\tsBackslash{}Huge text\} & {\Huge Huge}       \\
        \hline
        \tsCaptionLabelTable{Font sizes}
    \end{longtable}
\end{small}
    \end{BVerbatim}
    \tsCaptionLabelFigure{Tables}
\end{figure}

It is started with a block in one of the desired \nameref{sec:Font sizes}.
The first command within the font environment changes the spacing between the
text lines. If you do not do this, the table content and the table grid will
overlap or the spacing will be very tight. A good value is

\begin{figure}[H]
    \small
    \centering
    \begin{BVerbatim}
\renewcommand*{\arraystretch}{1.5}
    \end{BVerbatim}
    \tsCaptionLabelFigure{Row height in tables}
\end{figure}

The definition of the columns and their widths follows. Use
\tsTextMonospace{\tsBackslash{}linewidth} for the locally available width.
For a table with paragraph columns, its total width includes the sum of the
column widths, twice \tsTextMonospace{\tsBackslash{}tabcolsep} per column,
and \tsTextMonospace{\tsBackslash{}arrayrulewidth} per single vertical rule.
This total must not exceed the available width.

For example, a two-column table with three single vertical rules has a
column-width budget calculated as follows:
\begin{quote}
    \tsTextMonospace{\tsBackslash{}linewidth - 4\tsBackslash{}tabcolsep -
    3\tsBackslash{}arrayrulewidth}
\end{quote}
This calculation assumes ordinary column padding; custom intercolumn material
or double rules require their own allowance. A percentage such as
\tsTextMonospace{0.9\tsBackslash{}linewidth} is only a rule of thumb.
\bigbreak

To slightly separate column headings from the column contents, the\linebreak
\tsTextMonospace{\tsBackslash{}tsTextBold\{column name\}} command can be used. Each
column value is separated from the next column by a \tsTextMonospace{\&}. The end
of the row is marked with a \tsTextMonospace{\tsBackslash{}\tsBackslash{}}.
\bigbreak

For horizontal lines, a \tsTextMonospace{\tsBackslash{}hline} is inserted.
Place \tsTextMonospace{\tsBackslash{}endhead} after the column-heading row
and its horizontal rule to repeat those headings on every page.
When the first page needs a different heading, define it separately with
\tsTextMonospace{\tsBackslash{}endfirsthead}, followed by the continuation
heading ending with \tsTextMonospace{\tsBackslash{}endhead}.
\bigbreak

The data lines follow the same structure.
\bigbreak

To give the table a referencable name, add a
\tsTextMonospace{\tsBackslash{}tsCaptionLabelTable\{Font sizes\}} at the end.
Check the source of this document in the section \nameref{sec:Font sizes}
to see how it works.
\bigbreak

For verbatim source in a table, use a regular \tsTextMonospace{p} column.
Select \tsTextMonospace{BVerbatim[baseline=t]} for the code. FancyVerb's top-aligned box
aligns the first code line with adjacent text without negative vertical spacing.
The template retains \tsTextMonospace{P} as an alias for
\tsTextMonospace{p} for compatibility, not as a special alignment mechanism.
For a \tsTextMonospace{tsLTItemize} list, use a regular
\tsTextMonospace{p} column. The list is top-aligned with the text in adjacent
cells and stays together within its table row.
Also important is that the column separator \tsTextMonospace{\&} must be on
the next line after the \tsTextMonospace{\tsBackslash{}end\{tsLTItemize\}}.
